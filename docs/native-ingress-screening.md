# Initial whole-shaft ingress screen

`native_ingress.screen_axis_accesses()` is an isolated, opt-in preparation helper. It does not replace the shortest-local-exit baseline or call the patient loaders, native stroke preview, commit, policy, reward or training APIs. No patient execution has been performed for this slice.

Supply exactly six `IngressCandidate(axis, outward_sign, distance_mm, engine, proposer)` records, one for each source axis/sign. The future preparation adapter must obtain the unchanged exits and physical distances from `prepare_real_training_cases.derive_access`; this helper does not authenticate the centroid or independently rederive those distances. Axis/outward-sign labels must match the proposer’s authenticated source-axis/inward-sign descriptor. This narrow join explicitly pins the existing `permitted-nominal-cavity-columns-v1` schema and reads its sealed `_axis`, `_sign` and `_index_affine`; a provider-schema change requires review. It avoids introducing another affine tolerance after grid reconciliation. Each candidate uses an unchanged initial `NativeResectionEngine` and its source-bound `PreparedNominalCavityProposer`. Engines must have zero target labels. The physical masks, native affine, tools, aperture radius, support provenance, nominal target and proposal rule must agree across exits. Access-dependent source/model hashes may differ. The caller can prepare one engine per exit; this helper does not create six full task/action inventories.

For every emitted ray, the helper uses the same float64 `(tip-entry)/norm(tip-entry)` axis expression as native preview. `geometry.check_pose` checks the full rigid tool against hard exclusions, access angle, aperture, reach at entry and known image bounds. A separate `capsule_voxel_indices` call checks the shaft between `entry-working_length*axis` and `entry-tip_length*axis` against the initial tissue. The raw normalized axis is used for that capsule exactly as native microstep zero does; the separate hard check uses `ToolPose`'s existing normalization. Ordinary active-tip contact is allowed, but never recorded as removal here. Hard exclusions apply to the active tip as well as the shaft.

An exit is ingress-admissible if **any** emitted tool-entry pose passes. All six exits must finish before selecting the minimum `(distance_mm, axis, outward_sign)` among admissible exits. Neither the number of passing poses nor a target score ranks exits. Actor-crop coverage is a separate diagnostic and does not select access.

Exact byte equality of tool ID, float64 entry and raw normalized axis permits reuse of a static check within one exit. Endpoints in the same logical column are not rounded together: source/native grid reconciliation and arithmetic can give different exact poses. The limits are two tools, 78 declared slots/emitted rays per exit and 468 static checks total. Candidate-cap omissions refuse selection; ordinary unavailable/duplicate dispositions remain in the complete proposer ledger. No cancellation check is skipped because an earlier exit passed.

`IngressScreeningResult` retains immutable per-exit proposal dispositions, per-ray reuse links, hard-geometry failures/unknowns, shaft blocked-cell counts and lexicographic first blocked-cell witnesses in source indices and millimetres. Exported dictionaries are detached. Status distinguishes `selected`, `no_ingress_admissible_access`, `interrupted` and `failed`. An interrupted, capped, altered or otherwise incomplete screening returns no selected exit, retaining completed diagnostic rows. A final source/cavity/batch validation follows the final cancellation callback; no successful integrity check is cached.

Entry clearance is not complete-stroke feasibility. A selected exit still needs the unchanged full motion/causal native previews before any action is exposed. If those later previews yield no legal stroke, the caller must preserve that result rather than retry another exit according to outcomes. Outside-image tool geometry remains explicitly unassessed; a hypothetical aperture grants neither skull access nor clinical safety. Estimated-support and source-cell discretization limitations remain unchanged.

The helper has count bounds and cooperative cancellation only. Any future patient preparation needs a separately reviewed supervised resource declaration; no runtime speed or memory bound is established by these small analytical tests.
