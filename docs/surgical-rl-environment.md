# Surgical RL environment

`SurgicalRLEnv` wraps the existing deterministic `SurgicalEngine` and explicit V2 tissue profile. It provides reset, actions, observations, decomposed reward, episode boundaries, and replayable snapshots. It does not train a policy. Mechanics and reward weights are research assumptions, not calibrated patient outcomes or surgical recommendations.

The [verification receipt](surgical-rl-verification.json) records the checked source hashes, patient results, runtime measurements, and regression counts.

## Run and inspect

Install the optional RL dependency with `.venv/bin/python -m pip install -e '.[rl]'`. From the repository root run:

```sh
PYTHONPATH=src .venv/bin/python scripts/verify_surgical_rl_patient.py
PYTHONPATH=src .venv/bin/python -m pytest tests/test_surgical_rl_contract.py
```

For this checked patient, `outputs/surgical-patient-v2/rl-protection.json` binds eleven existing cached SynthSeg masks to the V2 grid: brainstem and bilateral thalamus, caudate, putamen, pallidum, and hippocampus. Their unreviewed estimate status is retained, with a 2 mm exclusion margin. Motor/language cortex, corticospinal tract, optic pathways, and cranial nerves remain unknown. The source masks are imported by `scripts/prepare_surgical_rl_protection.py`; they are not generated by the RL environment.

To rebuild that manifest from this Mac's existing collection:

```sh
PYTHONPATH=src .venv/bin/python scripts/prepare_surgical_rl_protection.py \
  --case outputs/surgical-patient-v2/patient.ressectionlab \
  --collection /Users/shaf/Downloads/RessectionLab-Native-Anatomy-sub-06 \
  --output outputs/surgical-patient-v2/rl-protection.json \
  --allow-unreviewed --include-hippocampus
```

The verifier starts separate intact patient episodes, checks public drill, CUSA, and vessel actions and rejection of a brain-retraction approach into the imported exclusion masks, and writes a JSON report and replay snapshots under `outputs/surgical-rl-patient`. Source anatomy is never pre-removed or replaced. All episodes can export native patient artifacts with their self-contained protection contract, including the guard-stopped partial brain approach. Native Save/Open restores that contract in the shared engine before replay, and subsequent desktop actions, branches, and resets retain the same protection checks. See [shared guards and latency receipts](shared-surgical-guards.md). Damaging verification trajectories deliberately use relaxed episode budgets; they are software tests, not successful treatment policies. A separate vessel-injury episode verifies negative reward and termination under the default damage budget. The report includes reset and action wall times and process peak memory.

## API and spaces

```python
from resectionlab.surgical_rl_env import SurgicalRLEnv, RLConfig

env = SurgicalRLEnv.from_patient(
    "outputs/surgical-patient-v2/patient.ressectionlab",
    protection_path="outputs/surgical-patient-v2/rl-protection.json",
    config=RLConfig(),
    render_mode="ansi",
)
observation, info = env.reset(seed=17)
action = env.encode_action({"slot": "left", "operation": "inspect", "duration": 0.1})
observation, reward, terminated, truncated, info = env.step(action)
snapshot = env.snapshot()
```

`step_action(engine_action)` uses the same transition path for existing engine recipes. `restore(snapshot)` restores an environment by replay, and `branch(position)` creates an independent episode prefix. `inspect_world()` provides the engine's detailed research view; `render()` provides an ANSI summary.

All fifteen instruments are selectable. Operations requiring absent membrane topology, attachments, bleeding sources, or functional evidence retain the engine's capability messages or explicit unknown results; selecting an instrument does not supply missing anatomy.

The fixed action is a Gymnasium `Dict`:

| Field | Meaning |
| --- | --- |
| `slot` | Left or right instrument slot |
| `operation` | Index into exported `OPERATIONS` |
| `instrument` | Index into exported `INSTRUMENTS`, all fifteen tools |
| `pose` | Seven float64 values: RAS millimeters xyz and xyzw unit quaternion |
| `use_pose` | Whether the pose participates in this action |
| `parameters` | Fixed float64 vector in exported `PARAMETERS` order |
| `parameter_mask` | Parameters explicitly provided by this action |
| `duration` | One float64 duration value in seconds |

The spaces expose raw physical values; a learning algorithm should explicitly normalize its policy inputs and actions. A pose is an absolute requested endpoint. Rotations retain all three orientation degrees of freedom, including roll; translation and rotation are checked by engine microsteps. Invalid quaternions are not silently converted into meaningful orientations. Initial placement and relocation must satisfy the wrapper's placement rules, while movement into anatomy uses checked public transitions. Occupied material is not bypassed by setting an endpoint or mutating a tool state.

The policy observation contains fixed arrays: `local` has shape `(2, 8, 9, 9, 9)` with material, target, protected membership, fluid, bone-temperature, displacement, cut, and known-grid channels; `slots` has shape `(2, 12)`; `tool_parameters` exposes each tool's current parameter values in `PARAMETERS` order; `metrics` follows exported `OBS_METRICS`; `coverage` reports supplied critical-structure evidence; `goal` contains four episode-goal values. The known-grid channel denotes sampling inside the source grid, not anatomical certainty. Inspect exported constants instead of assuming index order.

**The policy view is partially observed.** Local samples and aggregate metrics do not encode the entire Markov state. Pending drill work, temperature history, vascular compartments, wound sealing, cuts, deformation, holds, and remaining anatomy can affect future transitions. A policy may require memory. The engine view/snapshot is privileged debugging information and must not be silently treated as an observation available to an agent.

## Reward and stopping

Reward terms track new target removal and new harm or burden, with a cost for attempted actions. Bone removal has its own cost (`bone_removal_weight=0.05`) and does not consume the healthy soft-tissue removal budget or earn tumor credit. Healthy-tissue thermal exposure receives a separate monotone penalty based on volume-weighted power × time; it is an exposure proxy, not temperature or a validated injury dose. The bone-temperature observation comes only from the V2 drilling temperature model. The reward is a software objective, not a neurological outcome estimate. Repeated inspection must not earn removal reward; repeat suction must not earn credit for producing fluid; releasing tissue must not reverse previously charged irreversible injury. Invalid actions count toward attempt and invalid-action budgets even if the engine remains unchanged. Work-limited drilling is a partial transition, not automatically a collision or invalid action.

Termination expresses task success or configured harm failure. Step/time and invalid-action limits are truncations, preserving the distinction needed for value-function bootstrapping. After either flag, call reset before another step. Default limits are 128 attempted actions and 60 simulated seconds, with a maximum 5-second action. The success target is 95% of eligible target volume: protected target overlap is excluded from the denominator and never earns tumor-removal credit. The default damage budgets are 5 mm³ healthy-tissue removal, 0.5 mm² vessel damage, and 10 mm³ generated bleeding. Success remains subject to protection requirements and harm budgets. These defaults are configurable engineering choices.

The contract follows [Gymnasium's Env API](https://gymnasium.farama.org/api/env/): reset returns `(observation, info)`, and step returns `(observation, reward, terminated, truncated, info)`. The distinction between task termination and external time limits follows the [Farama explanation](https://farama.org/Gymnasium-Terminated-Truncated-Step-API). Seed the action space separately when reproducing sampled actions: `env.action_space.seed(17)`.

## Anatomy evidence and reproducibility

Protection requires explicit source masks and provenance; names alone do not fabricate anatomy. Original mask membership must survive material-ownership overlap. Missing critical anatomy is unknown, never an empty proven-safe region. The strict default requires brainstem coverage. Relaxing that requirement is explicit and suitable for declared engineering fixtures or tests of incomplete evidence; it does not establish patient safety.

Both instrument slots contribute proximity exposure during shared simulation time, including a parked inactive tool. Full swept tool geometry is checked before each substep. Indirect cuts, removals, thermal exposure, continuous deformation, and displacement of a grasped fragment containing protected cells are checked before committing the substep. The default protected displacement allowance is zero. These exclusion rules belong to the shared `SurgicalEngine`, so bare desktop and RL transitions use the same authoritative checks. They do not establish that every neurological structure has been identified.

Snapshots preserve the wrapper's attempted-action history and episode accounting as well as engine replay identity. Rejected attempts matter because they consume episode budgets. Snapshots include their `config` and `reward_config`; reconstruct those exact configurations and supply the same bound protection manifest before restoring an RL JSON ledger. Engine snapshots embedded in native archives additionally contain the exact source-bound protection contract; `SurgicalRLEnv.from_patient()` reads it automatically. The verifier checks the guarded brain snapshot in a separate Python process. Persist snapshots as JSON with `allow_nan=False`. A fixed patient, configuration, seed, and action sequence should produce matching observations, rewards, boundaries, and state identities after replay. Reset randomness and action-space sampling are separate reproducibility concerns.
