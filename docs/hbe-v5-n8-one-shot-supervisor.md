# HBE v5 N8 one-shot native supervisor preparation

This source-only preparation covers exactly `compression:N8:S60:reference` from the pinned [N8 canary proposal](../manifests/experiments/hbe-v5-n8-canary-source-only-v1.json). The proposed call would start a fresh FEBio process from the exact adapted Accelerate deck, save all 61 states, and run the v5 numerical stream readout. The tracked [one-shot preparation](../manifests/experiments/hbe-v5-n8-one-shot-preparation-v1.json) has `release: null`. No native call has been made under this preparation.

The separate release must bind the current full source commit and all 17 executing Python files, the pinned N8 canary manifest, old source deck, full N8 mesh, adapted deck SHA256 `3cf4156b19191918841498490bc448f88a61b656b566d5d6a3d36db817d0a724`, repaired `accelerate_csc_v1` profile and FEBio runtime, and only `outputs/mechanics/hbe-v5-n8-one-shot-v1/attempt-01`. The release remains an external, reviewed one-call decision. Running the module without `--execute --release <reviewed-file>` or with an absent/malformed release fails before it creates the attempt directory. The direct-file invocation is not the supported entry point; use `python -B -m scripts.mechanics_hbe_v5_n8_one_shot` from the repository root only after review.

The prospective limits are one attempt, 90 s wall time, 3 GiB sampled process-family RSS, 64 MiB active output, and one numerical thread. The historical old-endpoint N8 Accelerate control completed in 4.249919 s under a 90 s cap; its console, solver, node and element logs total 15,156,436 bytes. The new endpoint could cost more or fail. Those limits bound one attempt; they are not forecasts. Brief memory or output peaks between samples may be missed. Any timeout, resource violation, missing process observation, nonzero exit, descendant still running, unexpected output, backend mismatch, incomplete or malformed state, residual failure, or numerical criterion failure yields a retained failed receipt. No automatic retry exists.

The supervisor authenticates the source, canary, deck, mesh, runtime and existing same-runtime controls before output reservation, and rechecks released inputs after the call. It demands one actual `Selecting linear solver accelerate` line in both saved console and solver logs and refuses fallback wording. It retains the native `nodes.log`, `elements.log`, `solver.log`, `console.txt` and deck in the ignored attempt directory. The complete v5 stream reader checks all 61 native states, frame identities, residuals, fixture constraints, energy/work and recorded deformation; a clean FEBio exit by itself is never a numerical pass. The receipt labels any pass **numerical specimen software only** and keeps observed native output separate from generated fixtures. No measured force CSV, patient record, fitting response or withheld torsion is opened. All other eleven v5 rows, calibration, torque and physical-validation gates stay closed.

Source-only tests parse the actual historical N8/S60 Accelerate logs as 61 complete native frames and verify their residual grammar. Missing final frame, malformed header, removed final residual and excessive residual are rejected. The old-endpoint logs fail the new-endpoint v5 prescribed-motion test, as they should. Supervisor mocks cover absent release, malformed release, source/binding paths, actual backend selection, one-shot process-family termination and resource caps. These tests do not establish convergence at the new endpoint; only an independently reviewed release, one supervised native call and saved-output audit can address that numerical question. Even a successful specimen numerical run would not validate live brain deformation, cutting force or neurological harm.
