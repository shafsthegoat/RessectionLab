## Bounds and reporting

Limits are 180 seconds for the attempt, 170 seconds cooperative, a 174-second outer soft stop, a 178-second hard group cleanup point, 6 GiB sampled combined child-group RSS and one CPU thread. The executable path enters a small standard-library watchdog before importing project or scientific modules. It creates one process group containing orchestration, the native worker and their Git subprocesses; the local inner monitor deliberately does not create another session. The outer watchdog owns that actual group ID, always cleans it up, and rejects an exited leader that leaves descendants. Parent preflight consumes the same allowance and reduces inner supervision time. The final two seconds are reserved for cleanup verification and receipt publication; late publication is rejected.

Both child boundaries receive exact manifest and release hashes and verify them before preflight or decoding. A caught interpreter-observer exception permanently invalidates subsequent phases and reports prohibited-action counters as unknown, because CPython disables a failing callback. A missing observer is also a failure. Metadata-only CLI operations do not start a worker. The first standard-library timestamp starts the outer clock; Python startup before that timestamp and operating-system scheduling delays cannot be bounded by this Python watchdog. Sampled RSS may miss transient peaks. These are prospective bounds, not performance claims.

`receipt.json` stores authenticated `derived_exits`, original and selected full inventory/preview traces, the complete ingress receipt, before/after state and inventory hashes, unchanged reward/horizon, target actor coverage, empty initial cavity availability/counts, and entry/deepest-shaft centerline visibility. These visibility quantities are not finite-radius shaft clearance. Source masks are not exported; after-state hashes report untouched initial states. Unassessed out-of-image geometry remains an explicit unknown.

`supervisor.json`, `execution-baseline.json` and `acceptance.json` retain inner process/cap and provenance status. Sibling `<output-name>.outer.json` and `<output-name>.outer.log` retain the early outer lifecycle, combined group RSS, exact child byte pins, group cleanup, final acceptance digest and publication status. An inner acceptance alone is insufficient: saved-output acceptance requires the outer receipt to complete and bind its exact acceptance bytes. The outer sibling paths also prevent retry before an attempt directory exists. Partial phases stay `unassessed` or `not_executed`; overall screening/inventory failures remain incomplete. Passing ingress alone establishes neither a complete path, useful target removal, learning gain nor clinical access. Estimated support, narrow parallel columns and native-cell discretization remain limitations.
