# Explicit screened-access preparation

`prepare_native_access` is an opt-in source preparation helper. Existing callers of `prepare_real_training_cases._construct_task` still use the declared shortest-exit access and prepare the original inventory. The original `derive_access` implementation moved unchanged into `resectionlab.native_access_preparation`; the old script imports and re-exports that same function and rule constant. No second derivation algorithm exists.

The helper accepts an already validated, unexecuted `NativeSpatialTask`, exact cohort JSON bytes, a declared TRAIN subject, expected original source/model hashes and the saved access-derivation record. Expected hashes and derivation must come from the upstream subject-specific preparation record. The pinned cohort verifies the declared role; `NativeSpatialCase` has no independent patient identity field, so this helper cannot establish which patient's arrays a caller supplied. Existing CaseData/support/role/encoded-bundle joins remain mandatory upstream. A blocked source, including the unresolved PAT16/PAT20 sources, does not acquire a task or bypass support gates here.

Only annotation-assisted binary nominal evidence, the original source affine, unchanged observed support and the fixed 13-entry/two-tool/three-family proposer are accepted. The shared derivation reproduces all six distances, centroid/representative, boundaries and original access exactly. Six static sources then differ only in access. The existing ingress checker screens at most468 exact poses; ANY permitted tool-entry pass qualifies an exit, ranked by `(distance_mm, axis, outward_sign)`. It retains failures and outside-image unknowns. Neither private evaluator values, full-motion feasibility counts, actor coverage nor reward rank the exits.

The result contains a selected `NativeSpatialCase` and recursively immutable receipt. No selected task or native full-motion inventory is constructed, and no stroke, search or policy is executed. The caller must separately construct the selected task with the recorded unchanged reward/horizon and validate its complete inventory. If that inventory has no usable action, it remains the result; this helper provides no fallback. Cancellation, incomplete screening and final source/state mutation return no selected source. Invalid source/role/derivation inputs raise before screening.

Original preparation is a prior caller cost, explicitly recorded as already incurred with unknown elapsed time, its78 declared slots and actual emitted proposal count. It is never waived or treated as zero. New validation, candidate construction and screening durations are separate; `elapsed_seconds` starts at function entry and ends before the final immutable receipt copy. External whole-call timing remains necessary for a budgeted experiment. The helper performs no patient I/O and imposes no new runtime release.

Analytical controls cover exact legacy derivation/caller preservation, source and role joins, unchanged task state/tools/support/reference arrays, no preview or selected-task construction, copied immutable metadata, cancellation and no fallback. These are software controls, not patient evidence or clinical clearance. The initial owner test run exposed a tuple-versus-list assertion error against the deliberately immutable receipt; the assertion was corrected without changing selection behavior.
