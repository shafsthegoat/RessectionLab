# Case4 meshing follow-up: saved evidence and an untested candidate

This is a read-only investigation followed by documentation, not an execution release. No new patient array or landmark access, meshing, solver call, source/declaration change or parameter trial occurred. The [original result](../artifacts/mechanics/resect-case4-patient-mesh-v1/RESULT.md) remains a terminal count rejection: 2,065 nodes exceeded 2,000; medium/fine were not executed; independent volume-mesh quality and fidelity remain unassessed. No repaired sparse backend is assumed validated.

## Why increasing the node cap alone is insufficient

The saved [Gmsh log](../artifacts/mechanics/resect-case4-patient-mesh-v1/saved-records/supervision/combined.log) reports `Optimization starts (volume = 0.00113442)` and repeats that rounded volume during optimization. The worker's source-surface volume was 0.0011858776244957961 m³. Arithmetic gives `1 - 0.00113442 / 0.0011858776244957961 = 0.0433920191`, approximately **4.339% less volume**. This is a rounded library diagnostic, not the independently checked final tet10 volume or an accepted fidelity result. It is nevertheless a reason to investigate the boundary approximation before making the interior uniformly coarser. The prior analytic cube also failed its unchanged 3% volume gate.

The 2,000-node limit is an operational memory budget; the 2 mm bidirectional surface limit and 3% volume limit assess geometric approximation. Neither replaces the other. A simple scaling illustration from the observed 2,065 nodes gives about 2,974–3,568 nodes at 20 mm and 4,646–6,969 at 16 mm under respective h⁻²/h⁻³ laws. These are illustrative surface/volume scaling scenarios, **not predictions or rigorous bounds**: patch constraints, topology, feature sizes and midside nodes break uniform scaling. The fine limit of 4,500 could become restrictive even before boundary refinement. Solver memory and displacement/operator accuracy remain separate unknowns.

## One candidate: independent boundary and interior resolution

Gmsh supports a `Distance` field on discrete `SurfacesList`, followed by a `Threshold` background field that transitions from a smaller boundary size to a larger interior size. Distance uses sampled surface points; it is not an exact distance oracle. `Mesh.MeshSizeExtendFromBoundary=0` prevents automatic propagation of boundary sizes. Global `MeshSizeMin` and `MeshSizeMax` still clamp the field, so the current equal minimum/maximum would flatten any proposed variation. The `Extend` field is another established mechanism based on the existing boundary mesh, but would add staging to this experiment. These capabilities are documented in the [official size rules](https://gmsh.info/doc/texinfo/gmsh.html#Specifying-mesh-element-sizes), [size-field tutorial](https://gmsh.info/doc/texinfo/gmsh.html#t10) and [field reference](https://gmsh.info/doc/texinfo/gmsh.html#Gmsh-mesh-size-fields).

The narrow recommendation is to prepare **one fixed boundary-distance size profile** as a separately reviewed candidate, retaining the existing mesher, tet10 order, straight reference geometry, source mask and topology checks. Its boundary size, interior size, transition distances and distance-field sampling must be declared before outcomes; this note does not select successful values. Keep the original physical fidelity gates. Use no B/V landmarks, mask dilation, smoothing, hole filling or geometry adjustments. A finer boundary can increase total nodes despite a coarse interior; no current cap or accuracy success is claimed.

Preserving the source as an unchanged reference must be distinguished from retaining every original triangle in the output. Gmsh documents preservation of discrete entities without parametrized geometry; `Mesh.MeshOnlyEmpty` can also avoid remeshing existing entities ([official mesh options](https://gmsh.info/doc/texinfo/gmsh.html#Mesh-options)). However, this source has 91,951 vertices and 183,902 closed-manifold triangles. Retaining that triangulation requires 275,853 unique edges (`3F/2`); straight tet10 adds an edge midpoint per edge, giving **367,804 boundary nodes alone**, before interior nodes. This exact-triangulation route is incompatible with the present small-node budgets. A coarser remesh must therefore be described as an approximation to the unchanged source, with independently verified fidelity and topology; size fields do not guarantee either.

## Minimal diagnostic preservation for future rejections

Separate solver-eligible node counts from a small **diagnostic persistence allowance**. For example, a prospective 10,000-node / 20,000-tet ceiling gives `24N + 80E = 1,840,000` raw bytes for float64 coordinates and int64 ten-node connectivity. The failed coarse mesh would have needed only 133,720 bytes for those arrays. Save these available arrays and the explicit FEBio permutation, IDs, units/frame and hashes before the eligibility rejection, using a fixed byte ceiling, bounded writes and atomic completion. An unbounded native `.msh` export is unnecessary for this minimal record.

Crossing the eligibility cap must still reject the candidate and stop subsequent levels. Persistence does not authorize a solve, validation continuation or acceptance. If even the diagnostic byte/count ceiling is exceeded, retain counts and an explicit omission reason; never retain a misleading truncated mesh. The current attempt cannot be retroactively repaired because its rejected volume coordinates/connectivity were not saved. Any persistence change belongs to a new reviewed source version and release.
