# Generated full128 lazy-concat feasibility: pressure stop

This release preserves one generated-only full128 CPU attempt under the frozen V2 contract. The outer Python `-I` invocation first failed to import a sibling monitor module **before preflight, output creation, or any model call**; the separate launch-entry receipt records that setup error. The corrected `-B` invocation then passed preflight and began one model forward. It stopped when macOS kernel pressure changed from normal (mask 1) to warning (mask 2). The watchdog and post-run guard both report `kernel_pressure_warning_or_critical`; the worker exited from the watchdog signal, and no output logits or result were produced. There was no retry or cap change.

The corrected attempt ended after 3.004840 seconds with sampled process-group peak resident memory of 1,668,300,800 bytes, below the unchanged 3 GiB process-group RSS cap. The final fast sample had 41% available memory and mask 2. The worker's last completed phase marker was **before** encoder stage 3's first Conv3d. Full layer probes show substantial earlier encoder-stage allocations, including stage 0 and stage 1; no decoder stage or lazy final-concat operation had begun. This particular early pressure stop therefore cannot establish any benefit from the lazy decoder change, nor can it establish full128 model feasibility. One run does not isolate the model as the sole cause of system-wide pressure.

The supervisor recorded 55 fast and 6 slow samples, no monitor exception, and flat swap-used bytes. Every saved slow sample matched the exact live TractoInferno and IXI byte-intake identities and their bounded RSS allowances, with no blocking project overlap. The controller did not signal either downloader, and both were still live at subsequent inspection. Identity-checked finalization recorded no residual child, cleanup error, or manual-attention condition. The saved trace is the resource evidence; the earlier `-I` setup error is separate and did not consume a model attempt.

The generated input is not a patient scan, and the output is absent. Previous accepted 64³ baseline/lazy exact-logit parity and previous full128 tile4/tile1 pressure negatives remain separate evidence. This experiment does not validate patient accuracy, a search/RL comparison, a surgical action, or full-patch numerical parity against the native network.

All files in this compact package are source, contracts, hashes, logs and receipts. It excludes generated input arrays, checkpoint weights, patient imaging and any clinical labels.
