The pure three-stage example gives byte-identical logits and unchanged input/state and parameter/module aliases. The wrapper internally checks that its first stage-zero Python tensor has no remaining weak reference before decoder entry and that the decoder requests the recomputed skip exactly once. This proves a Python reference lifetime property, not released resident pages or useful peak-memory savings.

V2 closes the concrete V1 stage-one mutation counterexample in the tested scope. It now validates every encoder stage's exact `Sequential`/`StackedConvBlocks`/`ConvDropoutNormReLU` composition, bound forwards, Conv3d/InstanceNorm3d/LeakyReLU order, stateless norm, no dropout, and reviewed native or tiled Conv3d forward. It checks this both at attachment and at runtime. Preexisting module/global hooks are rejected, and hooks or later-stage forward changes added after attachment now fail before network computation. The generated tests exercise these rejections. The proposed trained branch also requires a five-stage decoder bound to the pinned lazy-concat forward; however that six-stage path has not been constructed or tested here.

Two runtime invariants remain implicit: the wrapper does not store and recheck the attach-time encoder/decoder stage counts, and it only compares the decoder `forward.__func__` to an expected function, not the attach-time decoder object, type or bound self. A changed graph may therefore reach an indirect shape/index error or execute a substituted decoder before an explicit contract failure. The narrow fix is to store the expected counts and decoder identity on attach, recheck them and the bound forward at each call, and add generated post-attachment mutation fixtures. This matters before claiming a fail-closed six-stage adapter; the current three-stage pure demonstration remains valid.

The runtime hook prohibition also means the prior 110 module-hook layer profiler cannot be attached to this candidate. A later resource control needs separately reviewed hook-free observations or an explicitly constrained passive-observer design, with the second stage-zero execution counted in timing and memory. Recomputing saves no proven macOS RSS yet: it retains the original input until decoding, runs stage zero twice, and PyTorch may retain freed storage in its allocator. A generated six-stage lazy-decoder parity test with exact logits and state/alias checks is the next bounded numerical gate; full-model/checkpoint use should wait for that and a prospective resource design.
