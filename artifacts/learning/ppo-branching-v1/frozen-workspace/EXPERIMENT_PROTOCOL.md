# Patient-specific optimization protocol

Protocol ID `patient-pilot-v0.1`, October 4, 2026. Implements the discipline in `MASTER_PLAN.md` §§9.8 and 15.8; those specifications remain authoritative. This document defines development runs and the later lock procedure. It does **not** assert that a public-case experiment, independent evaluation, population checkpoint or final cohort benchmark has completed. Results belong in saved run artifacts and factual status updates.

## Question and experiment labels

Does bounded scratch RL improve the modeled target-removal/hazard tradeoff or time to an acceptable candidate relative to per-case search, using identical permitted inputs, actions and constraints? Either method can win. The product default follows measured performance, and initial search candidates remain available next to learned candidates.

Use three labels without interchange: `synthetic_smoke` for software/analytic fixtures, `development_patient` for inspected public cases used in method development, and `locked_patient_evaluation` only after the outer procedure and cohort are frozen. Held-out worlds within a development patient do not make that patient an external validation cohort. A deterministic case is deterministic optimization even if it has many seeds.

## Eligibility and frozen record

Start with one UCSF-PDGM development case, supplied target annotations and a reviewed hypothetical intracranial access window. Verify actual image contents, source release/license, patient/visit identity, hashes, affines/units/orientation, labels, diffusion gradients and derivative transforms. Record absent or failed functional/vascular/skull evidence. Restricted structural results remain a separate capability track and do not count as a verified diffusion-aware patient experiment. Do not substitute synthetic functional structures for patient reconstruction without labeling that experiment synthetic.

Before every run, save the Git revision, dirty-state flag, dependency versions, input hashes and preoperative cutoff; `SimulationConfig` and its `decision_model_hash`; tool/access/objective/action-generator versions; world manifests; optimizer configuration; hardware; and the analysis version. A case/model/reward/tool edit creates a new experiment ID and invalidates dependent candidates. `FrozenDecisionModel` can additionally snapshot the complete decision contract. Timing-unknown molecular/pathology fields are unavailable in the primary preoperative analysis; the planner must work without them.

## Executed methods and resource rules

| Arm | Definition | Pilot rule |
|---|---|---|
| `STOP` | Terminate before a removal action. | Always available; report its residual target and zero removed volume. |
| `SEARCH` | Legal straight-route enumeration for accessibility; greedy plus bounded beam/trajectory search for sequential removal. | Use the identical simulator/action generator and full-tool hard constraints as RL. Save all attempted candidates and termination reasons. Do not compare route accessibility with RL removal as though they were one endpoint. |
| `PATIENT_SCRATCH_RL` | Fresh `MaskedPatientPolicy` with actual gradient updates through `train_patient_policy`. | Three optimization seeds: **11, 23, 47**. Each is a separate initialization on the same patient and world panel. |
| `POPULATION_FROZEN` | Shared policy trained only on eligible development patients; no case updates. | Add when a provenance-audited shared checkpoint exists; missing is not a measured failure. |
| `POPULATION_ADAPTED` | Fresh clone of that shared policy, updated only for the current case. | Same bounded adaptation/selection rule; never carry one evaluation patient's updates into another. Required in the full four-arm benchmark. |

The implemented scratch baseline is **masked REINFORCE with a learned value baseline**, not PPO. Initial `TrainingConfig` defaults are 4,096 optimization environment steps, 128 gradient steps or 60 seconds, whichever limit is reached first; horizon 64, four episodes per update, selection every eight updates, 32 hidden features, Adam learning rate 0.003, discount 1.0, entropy weight 0.01, value weight 0.5 and gradient clipping at norm 5. These are engineering pilot settings, not literature-derived clinical parameters. Save the actual configuration; simulator horizon may be shorter.

Policy rollout reserves its last action slot for STOP. The runner gives every arm an effective non-STOP horizon of `min(simulator.max_steps, policy.max_episode_steps - 1)` and saves requested/effective values. Search cannot receive an extra removal action merely because its termination bookkeeping differs.

Charge selection time to online RL cost. Count optimization and selection transitions separately. Search receives the same online wall-time allowance and a separately counted transition/evaluation budget; make a matched-transition comparison as well as the time curve. Candidate generation, scene preprocessing, selection and independent validation costs must be logged consistently. The runner gives each arm/seed a fresh geometry cache and records its preparation time, so a preceding search does not supply RL with free cached candidates. Immutable anatomy is shared. Population pretraining is never hidden in an inference-only speed claim. Resume retains total resource limits. Wall-time comparisons run arms serially under the same workload and record concurrent processes/thermal or device changes when observable; unit-test timing is not a product benchmark.

No method gets latent world transforms, true tract positions, future images, postoperative labels or a richer action set. The same `SimulationObservation` and legal action mask go to search and RL. Hidden truth can score simulated events; it cannot rank deployed actions except through observations explicitly allowed by the protocol. More search proposals for one arm must be a separately named ablation.

## Within-patient world and checkpoint split

`generate_partitions(case_hash, generator, master_seed=20261004, planning_hash=case.planning_hash)` defines the initial patient panel sizes: **16 optimization, 8 selection, 16 final-evaluation and 8 stress worlds**. All arms/seeds for that case use the same saved panel, while policy initialization seeds remain independent. Hash-derived world seeds include the permitted preoperative planning hash, role and index, so unavailable future context cannot alter the sampled worlds. Full case identity is retained separately for provenance. Synthetic fixtures can use their case hash. `WorldPartitions` rejects overlap, differing primary generators and reuse of the primary family for stress.

The simulator's actual sampling behavior must match the saved generator. `SimulationConfig.world_generator`, `SequentialSimulator.case_hash` and `world_generator_fingerprint` bind the manifests to the physical sampler; reject inconsistent manifests. The legacy `world_translation_voxels` convenience input resolves to an explicit physical uniform generator and must not be mislabeled Gaussian. The sampler rigidly transforms functional fields and graph masks, leaving tissue geometry/hard exclusions fixed. Boundary coverage is tracked separately and its conservative surrogate penalty is recorded; unknown event outcomes must still remain unknown. A seed-role check alone is insufficient evidence of uncertainty validation. Run the sampler/adapter tests before nonzero patient sensitivity experiments.

After that gate, the first registration-only sensitivity scenario may use the implemented `WorldGeneratorConfig` Gaussian family with declared 1 mm translation scales, zero rotation and an independent uniform or directional stress family. Freeze these uncalibrated assumptions before optimization. Report the exact parameters and distribution support; a Gaussian standard deviation and a uniform bound have different meanings. This does not reconstruct tract uncertainty or validate biological deformation. Keep one coherent hidden anatomy fixed per episode. Missing anatomy stays unknown; cropping or shifting it out of view must not lower a cost silently.

Training receives optimization and selection manifests only. Checkpoint selection maximizes mean deterministic-rollout return across the complete selection panel; the initial checkpoint is eligible and earliest checkpoint wins ties. If cancellation/resource exhaustion prevents a complete selection pass, retain the last completely evaluated selection candidate and label the interruption. Do not call training return independent performance. Freeze selected checkpoint and retained candidate hashes before opening final-evaluation or stress results.

For a tradeoff collection, repeat the same frozen procedure over a **predeclared** small preference grid and retain non-dominated candidates using selection outputs only; store that grid before running it. The single default preference run is an optimization smoke/pilot, not proof of a full Pareto frontier. Any extra exploratory preference created after reading evaluation results starts a new development experiment.

## Geometry and reward acceptance before patient training

Run the adversarial/analytic suite before a patient run. Required behaviors are shaft collision despite tip clearance, swept collision between valid endpoints, entry aperture/reach, connected exposed-frontier removal, paid intervening normal-tissue removal, no duplicate removal benefit, one-time graph cuts, STOP, stale action rejection, reproducible replay and model-change rejection. Exercise missing gradients, left/right errors, nonfinite inputs, tool cycling and unavailable evidence. A high-return exploit is a simulator defect; affected runs become invalid.

The current `RewardSpec` has target 1, normal 0.2, motor/language 2 each per mm³ of their declared fields; action and tool-change costs 0.02; motion cost 0; and graph-edge cost 1 per newly interrupted modeled edge. These are surrogate preference units. Record compartment labels/weights and all cumulative terms. This scalar reward is an optimization aid; clinical deficit probabilities remain null. Accessible volume is separate from legally replayed removed volume and modeled residual volume.

Final candidates need independent geometry evidence. Replaying the training checker at the same resolution is a regression check, not independent certification. `evaluation.py` implements separate segment-to-cell/capsule checks and a continuous-motion conservative envelope with a 0.25 mm default surface-step bound; orthogonal/oblique grids are supported, shear is rejected, and rotating aperture certification can be unsupported. The experiment runner rechecks each insertion against the current cavity with this implementation, direct six-neighbor frontier checks and removal accounting. Its coarse certificate is conditional on the supplied discrete suction footprint and simulation grid.

For patient bundles, `independent_native_removal_check` additionally maps claimed coarse removal back to source cells and requires complete source-cell containment within the active-tip capsule. The runner saves both certificates and makes failed or missing native checks invalidate the candidate before world-outcome reporting; a coarse pass cannot overrule a source-resolution failure. Native complete-tool replay and tissue mechanics remain distinct gates. Record actual tolerance/resolution and passed analytic tests with every report. Persist `freeze_candidates(...)` output and `EvaluationLedger.to_dict()` before/after `evaluate_frozen_candidates(...)`; its final/stress-only interface is not a substitute for saving that ledger across sessions. Full validation, each native/coarse check and each evaluation partition have separate elapsed-time records.

## Evaluation outputs and analysis

For each frozen candidate/patient/seed/world, save method and checkpoint IDs, selected actions, tool/access settings, feasibility and first failure, target accessibility, legally removed/residual target by radiological compartment (mm³), normal removed volume, spatial motor/language surrogate costs, newly cut modeled edges, effort, STOP reason and all unassessed factors. Save numerator/denominator for each precisely defined structural event, e.g. `motor_structure_contact`. Unknown evidence is neither a negative event nor a zero probability.

Report independent hard-constraint failures; removal or accessibility at fixed, declared surrogate budgets; non-dominated candidate count and access/tool diversity; mean, adverse quantile and CVaR cost; model-family ranking changes; and quality versus total online time. Hypervolume is secondary and unavailable until normalization and its reference point are frozen. Mean reward alone is insufficient. Keep finite-world Monte Carlo intervals separate from model-family variation. Initial panels are small pilot panels and cannot estimate rare clinical harms.

For one patient, report descriptive paired results across the three optimizer seeds and explicitly **n = 1 patient**. Seeds, trajectories and worlds are within-patient repeats. Across a locked multi-patient cohort, aggregate repeats within each patient and use paired patient-level differences and patient-cluster bootstrap intervals, with repeat visits/derivatives grouped. Include all failed imports, reconstruction failures, invalid candidates, timeouts, cancelled runs and abstentions with reasons; never remove them from the denominator because their scores are inconvenient.

Every run writes a result status (`completed`, `cancelled`, `failed`, `invalidated`), settings, resource counts, candidate/evaluation records and a concise interpretation linked to the raw artifact. Preserve negative findings, including no checkpoint improvement, RL losing to search, STOP dominance, geometry disagreements and unresolved anatomy. Do not populate an experiment table with proposed numbers or treat a missing arm as zero performance.

## Reproducible entry point

From the installed repository environment, the default three-seed synthetic comparison is:

```sh
.venv/bin/python scripts/run_patient_learning.py --output artifacts/learning/synthetic-protocol-v1
```

The output directory must be new. The runner saves exact source bytes plus per-file hashes (including uncommitted code), actual configuration, search/training records, candidate hashes, a separate evaluation run ID, the exposure ledger and full replay metrics. Changes to numerical runtime code invalidate the attempt; unrelated UI/documentation edits remain recorded without stopping the numerical run. Final evaluation replays fixed sequences selected before those worlds are opened. Structural-contact event counts are not implemented in this runner, so it does not invent them from nonzero hazard values. `--case-bundle` supplies the native source case for audit and permitted seed identity; callers of the Python API pass `source_case=case`. Development-only patient callers without a source object must supply its explicit `planning_hash`. A run with any rejected candidate returns `invalidated` and lists those candidates while retaining all diagnostics and valid abstentions.

Use `--development-only` for configuration screening: final/stress evaluation is never called. `--hidden-features`, `--learning-rate`, `--entropy-weight`, `--episode-steps`, resource limits and `--world-counts` expose explicit saved overrides. Small-panel smoke runs are labeled by their actual configuration, not retrospectively called the default pilot. Use `--case-bundle` with a saved, reviewed case to run the patient factory. Its current coarse structural mode preserves source compartment-volume fractions but treats a contacted coarse cell as an indivisible removal; it is not native-resolution resection or a functional-risk benchmark. Missing motor/language evidence remains null in reports.

`tests/test_experiment_runner.py` checks source-change detection and exact snapshot retention, independent rejection of an inaccessible sequence, frozen/disjoint evaluation artifacts, overwrite refusal, the development-only evaluation barrier, equal action horizons and rejection of a coarse pass whose claimed tissue lies outside the native removal footprint. Orchestration tests use private stable source fixtures so concurrent UI editing cannot race their snapshot copy; production source protection is retained. These software checks do not substitute for the public-case comparison.

## Development now, locked evaluation later

Development may revise implementations and assumptions based on development-patient results; each revision keeps the old attempt and creates a new versioned run. Newly exposed final worlds from a development run may inform another development experiment, but lose their untouched status. Current work does not constitute a locked external benchmark.

Before any final cohort comparison, freeze unique-patient/overlap manifests, all four arm implementations, upstream model provenance, preference/surrogate budgets, adaptation budget, candidate/checkpoint selection, world/stress families, exclusions and the analysis script. Hold UPenn out of this global method development. Each held-out case may then use permitted preoperative inputs for the already frozen scratch/adaptation procedure, with isolated optimization/selection/final worlds. UTSW is a structural test unless its diffusion contract is independently established; RESECT remains independent of ReMIND registration development. No cross-patient adaptation-state transfer or method revision based on final results is permitted.

Reproducing a known synthetic optimum establishes a software property. Passing a public-case simulation establishes within-case modeled behavior. Broader claims require the frozen patient-level benchmark, independent reconstruction/geometry checks and publication artifacts; neither establishes clinical efficacy.
