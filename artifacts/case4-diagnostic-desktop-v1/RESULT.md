# Case4 diagnostic layer: desktop integration checkpoint

The local Electron workspace now has a saved-only, display-only import path for the independently audited Case4 DEVELOPMENT diagnostic descriptor (SHA-256 `d5d2ec1e8d2f99ec1842d4f4d1509986158075fea6cbb56d62718f1a2f8a18b4`). It binds the selected atlas-prepared T1c image, checks the two saved NIfTI byte hashes and authoritative sforms, and carries signed state (`-1` unknown, `0` covered candidate-negative, `1` covered candidate-positive) separately from binary output coverage. The MRI-plane viewer hatches unknown voxels and outlines positives. Loading this layer suppresses routes, replay and planning overlays; it does not alter CaseData or run the model. The recorded layer has 2,625 positives, 1,116,094 covered voxels and 7,811,906 unknown voxels. These are output counts, not tumor accuracy or clinical evidence.

The [initial independent source review](reviews/REPORT.txt) approved the 23-file non-App candidate and the two isolated App patches. The fixture now has nonconstant generated intensities; the production call uses the existing strict `json` path mode. The [independent repair addendum](reviews/CANONICAL-REPAIR-ADDENDUM.txt) checked those exact narrow deltas, plus the wording correction from “native grid” to “separate image grid.” No admission or numerical rule was weakened.
