No model call had occurred at review time.

The direct macOS sampler's 32-byte `xsw_usage`, 96-byte `proc_taskinfo`, and 136-byte `proc_bsdinfo` agree with the local Apple SDK. [Apple libproc source](https://github.com/apple-oss-distributions/xnu/blob/main/libsyscall/wrappers/libproc/libproc.c) confirms `proc_listpgrppids` and `proc_listchildpids` return PID counts. The sampler queries kernel pressure mask, available percentage, and swap-used bytes directly, then unions same-process-group PIDs with a bounded recursive descendant list. It measures all currently reachable model descendants even if one leaves the PGID and stops on such a detached descendant. It fails closed on enumeration truncation, unreadable resident/start data, unknown pressure, and missing group while the worker is alive. The 3 GiB cap is sampled resident bytes, not an atomic hard memory limit.

The all-process `ps`/`vm_stat` inventory runs in a separate half-second thread and cannot block the 20 Hz fast loop. A failed inventory command or parser stops the child; absence/staleness over 1.5 seconds also stops it. Errors before launch and after child exit prevent `accepted_for_pair`. The 30-second preflight and child retain the prospective normal kernel mask, available-percentage, swap-used growth, RSS, wall-time, log-size, and overlap limits. Global compressor/pageout/swapout counters are diagnostics; isolated increments have no independently validated injury or host-failure threshold. The unchanged worker requires `weights_only=True` with a four-entry scoped NumPy allowlist, pinned model/input hashes, strict architecture and alias checks, FP32, MPS fallback disabled, and a bounded MPS allocator before MPS tensors. The unchanged comparator requires accepted CPU and MPS supervision receipts plus `rtol=atol=1e-3` logits and exact decoded labels, with threshold-margin diagnostics. These checks are generated software controls, not patient accuracy evidence.

The one allowed ReMIND TRAIN acquisition process is bound to exact PID/PGID/start/ucomm/full-command hash/source-script hash/declaration hash and ≤1 GiB RSS; a mismatch stops only the model child. A read-only independent snapshot rechecked the pinned manifest SHA and saw `identity_matched=true`, `rss_within_cap=true` at 47,248 KiB. Other project processes were also present in that snapshot, so a model launch at that instant should defer until the root's exclusive compute window. No raw process command arguments are written to receipts. The generated controller benchmark with acquisition active recorded 36 samples, max direct sample 0.198 ms, max gap 60 ms, and no slow errors. A separate generated detached-child fixture counted both parent and detached child (78,643,200 resident bytes) and showed a wrong start identity was not signaled while the matching generated child was. These tests validate controller behavior only, not nnU-Net forward behavior under memory pressure.

Detached cleanup rechecks kernel `(pid,start seconds,start microseconds)` immediately before a targeted signal. This sharply reduces stale-PID risk but is not an atomic process handle; a narrow check-to-signal race remains. The model worker has no intentional detached subprocess path, and the controller records each cleanup decision. Any observed detach or cleanup uncertainty should be treated as a failed control requiring manual inspection before further model calls. The acquisition process is not targeted by the controller. Future checked-in reuse should retain these limitations and versioned receipts rather than claiming a production-grade hard sandbox.
