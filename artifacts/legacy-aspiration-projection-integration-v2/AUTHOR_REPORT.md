# Bounded legacy RL256 → shared generated episode integration

The released RL256 checkpoint is an actual trained `SpatialPolicy` for the older two-step, 9×9×7 generated opening task. Its actor requires an exact `SpatialObservation` v1 with six image channels and 16 geometry columns. The current desktop generated episode is a different 13×13×12, six-step aspiration-plus-probe task returning `SequentialSpatialObservation`. Passing that mixed observation to RL256 fails correctly. Using `.base` directly would expose probe rows as ordinary aspiration candidates and is invalid. This is a transfer experiment to another generated fixture, not an evaluation on the checkpoint's training distribution or a claim of mixed-tool competence.

The ignored candidate `resectionlab/legacy_aspiration_projection.py` constructs a fresh validated v1 DTO retaining only STOP and certified aspiration rows in original order. It retains all existing observed image, availability, coverage, geometry and state fields; native action IDs and the underlying task stay unchanged. It refuses a prior committed probe or observed probe-contact state, including later native mutations through an alias. `AspirationOnlyNativeTask` applies the same restriction in policy and search clones, transition methods and replay. `BoundAspirationTransferPolicy` records the existing safely loaded actor identity together with this projection, target generated source/environment and permitted tool IDs; it adds no fitted parameters.

The candidate paired entrypoint runs both the actor and `observed_beam_search` from a nominal-only planning clone with the same projected legal actions. It independently replays both shared records and seals each decision's projected fingerprint against the full mixed inventory fingerprint and excluded probe IDs. Private vascular reference labels are not loaded or scored by this entrypoint. In this fixed fixture the actor crop is the entire 13×13×12 source, so both arms have the same nominal field extent; search explicitly scores each simulated transition from that field while the actor uses its learned encoding. The result has no patient, clinical, force, or physical-validation claim.

The actual legacy rollout already proved safe RL256 loading and two actor forwards on its original generated task (`build/legacy-RL256-shared-executed-v3`): RL modeled return 1.098. Its beam-width-two smoke search used 9/24 transition calls and returned STOP. A separate width-four search used 15/24 calls, pruned no prefixes, and found 1.100 on that fixed task. Thus neither prior result establishes an RL advantage. This candidate has **not** loaded that checkpoint or executed a trained transfer forward.
