# Prospective v2 initial-host policy assessment

**Provisional until independent saved-output audit.** The committed v1 launcher still requires 55% availability and normal pressure before validation, plus separate unchanged 45%/normal checks before native reservation and supervision. Nothing here edits v1, creates an executable v2 release, or authorizes a native call.

The one read-only probe used a **50% admission floor** but actually started at **54%/normal**. Its worker's first saved host snapshot was 53%; 27 supervisor samples had a minimum of 53% and ended at 54%, all mask 1. The 24 worker snapshots likewise had minimum 53% and ended at 54%, all mask 1. The original validator completed in 5.470 s outer wall; all 14 eligible predecessor opens were hinted for 2,801,621,755 B, exact deck/source/prior receipt guards passed, and no native/readout call or HBE output reservation occurred. This measures one **54%-start** read-only verification. It does **not** empirically test starting at 50% or guarantee how the host will respond during a future FEBio solve. The previous unhinted 55%→40%/mask 2 diagnostic and hinted 55%→55%/normal arm were run under different host/cache conditions; a causal no-cache benefit remains unproved.

A narrowly reviewable prospective **v2 initial floor of 54%/normal** is the largest relaxation directly aligned with a saved start state: it would reduce v1's initial threshold by one percentage point while retaining the 45%/normal pre-reservation and immediate pre-supervision guards, exact unchanged source/deck/receipt checks, one-use policy sidecar, native/readout ownership, all elapsed/RSS/storage caps and no retry. The observed 54% start was nine percentage points above 45%; the observed 53% minimum was eight points above it. On a 16 GiB host those percentages are roughly 1.4 and 1.3 GiB of *reported availability margin*, not a guaranteed allocation or safety reserve. One successful read-only run at 54% is feasibility evidence, not a calibrated lower bound for repeated validation or native memory use. Any v2 code and envelope would require independent source review and generated threshold/adversarial tests, then a fresh source-bound host snapshot and a separately reviewed one-use native release. A failure at either 45% gate must remain terminal with no retry.

There is **no direct basis to set v2's initial floor to 50%** from this result. A 50% start has only five reported points above the unchanged native gate, and this probe never encountered that state. If 54% remains persistently unavailable and a broader relaxation becomes necessary, the next measurement would have to be a separately authorized read-only start near that lower range, with the same full validator and host series; do not reclassify this 54%-start run as that measurement or run an unbounded sweep. Clinical force, material properties, brain shift and patient transfer remain unvalidated by all of these host-engineering observations.
