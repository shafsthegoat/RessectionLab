# Prospective review: generated CPU native versus depth-tiled network control

**Decision: GO for one native CPU arm after the N32 heavy slot and an accepted fresh host preflight. HOLD the tiled arm until independent audit of the native receipt and logits.** No model call was made in this review. The experiment is a generated-input numerical control at `[1,2,32,32,64]`, not 128³ production inference or patient validation. Gate A v3's pressure-stop negative remains unchanged.

The pinned `3d_fullres` plan has Conv3d kernels 3³, stride 1 then five stride-2 stages, and patch `[128,128,128]`. The test input contracts to `[1,1,2]` at the deepest stage, leaving two spatial cells for InstanceNorm. The installed `SimpleConvBlocks` source applies `(kernel−1)//2` padding and dilation 1; the reviewed tiling operator preserves the full depth receptive-field halo for every output slab. Its six small generated cases passed exact Conv3d parity. The tiny generated Conv3d+InstanceNorm wrapper test preserved all recorded parameter, state-dict storage, and module identities, but full-block max difference was 7.15×10⁻⁷, so full-network bitwise equality is not presumed.

The worker uses the pinned isolated CPU/FP32 runtime, generated nonzero input only, SHA-checked plans/dataset/checkpoint, a four-entry scoped NumPy allowlist for `torch.load(weights_only=True)`, strict key/shape/value copy and duplicate-alias checks. In the tiled arm it patches only unique plain `Conv3d.forward` methods after loading and evaluation; ConvTranspose3d, InstanceNorm, other modules, weights, and state-dict identities remain as loaded. An added one-second timeout bounds its `ps` phase probe. Both arm scripts and the unchanged fast/slow host monitors are SHA-pinned in the contract; arm receipts bind the same contract and checkpoint hashes.

The supervisor retains the 22 Gate A v3 resource-policy fields: 30-second normal-pressure preflight, direct ~20 Hz macOS pressure/available/swap and descendant-aware RSS sampling, fresh background process inventory, 3 GiB process-group RSS and 120-second wall caps, exact acquisition-worker allowlist, and no patient or MPS execution. The tiled arm refuses to start without an accepted native receipt tied to the same contract/input/checkpoint. The comparator requires both accepted receipts, finite contiguous `[1,3,32,32,64]` FP32 logits, unchanged source/contract/checkpoint provenance, `rtol=atol=1e-3`, and exact sequential region-decoded label agreement; it records out-of-tolerance counts, threshold crossings, and margins rather than changing criteria after inspection.
