# Generated persistent-passive episode: exact desktop seam

This is a source-only integration note, not execution or patient admission. It follows the opt-in `PersistentPassiveTask` and `export_passive_episode` frozen under `stage/resectionlab/persistent_passive.py` (source SHA-256 `2b431550499d2165ff868236bd46e65eb0a6a28410355576db528d4509c4d5c4`). The paired-tool version declares five actions—`PASSIVE_MOVE`, `ACQUIRE_GENERATED_STATUS`, `PASSIVE_WITHDRAW`, `PASSIVE_WITHDRAW_STATIONARY`, `STOP`—and therefore exports six action-boundary frames including the initial state. Both tool states remain in every snapshot; their depth-retention changes only at explicit withdrawals. The clock is a declared generated schedule in seconds, not observed operative time. The fixed analytic source now includes a declared 3×3 pre-existing free tunnel through generated tissue, with the held pose at z=6.5 inside that void; no episode-time material removal creates the tunnel. This is generated geometry, not patient anatomy or a validated surgical interaction.

The legacy path cannot serve as a continuous episode. `src/resectionlab/development_episode.py::replay_frames` appends insertion microsteps and then reverses them for **each** aspiration/probe stroke. `desktop/src/native-episode-replay.ts::hydrateNativeEpisodeReplay` reconstructs precisely that insertion/withdrawal order and one `recordedTool` per `ViewerReplay`. Reinterpreting those frames as retained tool state would be false. Leave v1 and its learned-transfer, search, save/reopen results unchanged.

The frozen exporter provides schema `resectionlab.generated-persistent-passive-episode.v1`, `sourceHash`, `decisionModelHash`, `protocol`, ordered `actions`, `history`, `physicalHistoryCanonicalJson`/`physicalHistoryHash`, `frames`, `frameMeaning`, `finalStateHash`, `scope`, and `episodeId`. Each frame is `{frameIndex, operative}`. Each `operative` snapshot includes phase, `elapsed_generated_seconds`, `moving_tool` and `other_tool` records (`tool_id`, `pose`, `activation`, `retained_at_depth`, `pose_status`, `physical_absence_claim`), and `inspection_status`. A withdrawn tool stays represented at its access pose with `physical_absence_claim: false`; `retained_at_depth: false` must not be rendered as disappearance. The inspect/STOP events are in the corresponding history row, not separate frame fields. A desktop response wrapper must additionally bind the generated display `CaseData` identity, RAS+ affine, source image/support/nominal-target digests and two tool-geometry records; the bare export cannot be admitted against an arbitrary case. Re-derive each frame from the exact action history/protocol or a fresh backend task replay, verify operative-before/after digest ancestry and the unchanged native cavity/contact masks, and reject nonmonotonic time, missing/teleported poses, skipped withdrawal, changed source/tool identity, or status visible before inspect. The task's native engine state hash stays unchanged during this passive episode, so it cannot by itself prove pose or clock continuity. Show snapshots only; the current motion check does not supply time-resolved intermediate trajectories.

`src/resectionlab/desktop_bridge.py::executeDevelopmentEpisode` and `desktop/electron/development-episode.cjs` presently admit only `generated-sequential-v1` and `shared-native-development-episode.v1`. Add an explicit fixed-fixture/schema branch or a dedicated generated operation with a separate result validator; never widen the v1 validator to arbitrary episodes. `src/resectionlab/workspace_bundle.py::validate_episode` must regenerate or fresh-replay this fixed passive action sequence before reopening, then retain the existing case/source/session hash and frame-index checks. The Electron saved-workspace validator (`desktop/electron/workspace-session.cjs`) and React loader (`desktop/src/workspace-session.ts`) must dispatch to the matching v2 validator/hydrator. A digest alone is not replay authority. The old `episode-authority` learned-policy attribution checks do not apply to this scripted passive fixture.

The renderer has the physical capacity for two capsules: `VolumeRenderer.recordedTools` is a `THREE.Group`, `instrumentCapsuleMeshes` draws a full shaft/tip, and MRI slice shaders have two tool-uniform slots. It does **not** yet have a two-tool replay contract: `ViewerReplay.recordedTool`, `recordedToolDisplay`, `recordedEpisodeBounds`, `VolumeRenderer.recordedDisplay`, and `syncInstrumentDisplay` are singular and assume aspirate/probe insertion/withdrawal. Use a distinct passive replay frame/validator with an ordered array of up to two checked poses, paired bounds, and two uniforms/mesh children. Do not mark pair geometry independently validated: the staged task's independent checker covers tissue motion only, while stationary-tool clearance comes from its primary geometry check. UI text should say generated passive geometry, generated clock, generated inspection status, and no tissue interaction/clinical outcome claim.
