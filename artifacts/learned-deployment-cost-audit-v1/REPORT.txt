Current learned deployment still pays for exhaustive candidate legality

Finding: the current actor has no demonstrated latency advantage over native greedy at the same visited states. It can avoid a branching beam search, but native greedy is the relevant cheap comparator: most of the expensive work is already completed to construct the actor's legal-action input. This is a deployment-cost finding, not a claim that the methods make equally useful decisions.

Source path
NativeSpatialTask.__init__ calls reset -> observation -> _prepare_inventory. Every emitted base proposal receives a full native preview before the observation exists. With obstruction_opening enabled, those previews also supply the bounded public blocker evidence; added proposals then receive their own full previews. Only feasible motion certificates enter the actor's action list. SpatialPolicy.forward therefore starts after candidate enumeration and legality checking. STOP cannot currently bypass this initial inventory. A motion invalidates the inventory; step eagerly constructs the next observation. Cached repeated requests and planning_clone reuse certificates, but each newly visited state needs a new inventory. _transition also requires the complete inventory, so merely delaying observation construction would not provide a lazy-action path.

Native greedy uses those same certificates' already-computed contained-cell removals to score the permitted nominal target and frozen costs. It commits only the winning action on a planning clone; it does not create a successor branch for every scored action. There is no private-reference benefit: planning_clone substitutes the public nominal target. Policy and search share permitted source data, but their effective access is not identical: the actor has the bounded crop/ray/global-context representation, while nominal scoring accesses the full permitted target at certificate removal indices.

Beam selection took 219.388330 s and 60,338 additional previews. Avoiding this cost is credible, but native greedy achieved the same STOP outcome far more cheaply too. A speed claim against beam alone would conceal that baseline.

Smallest future experiment worth considering (not implemented or selected for the active runs)
A separately declared lazy verified-action shortlist on the new-four historical proposal condition could test whether reducing native queries creates a real model advantage. Keep the permitted world, tools, costs, complete-tool verifier and underlying geometric candidate pool fixed. A learned ordering would see public observation + uncertified candidate geometry, explicitly without a free legal mask or hypothetical removal outcomes; verify only a single predeclared bounded shortlist and admit only currently certified chosen actions. Every failure/query counts, and STOP remains available. Compare the learned selector and nominal greedy over that exact same verified shortlist, with exhaustive native greedy retained as the quality/cost reference. Report full-route return, missed useful actions, failed previews, total verification queries and end-to-end wall time, including independent replay separately. A faster but inferior/unsafe route is not success.

This requires an explicit observation/action-admission adaptation: current policies were trained on already-legal candidate lists, and _transition reconstructs all candidates. It is not a safe switch on existing checkpoints. On an obstruction-enabled condition, all base queries used to discover blocker-centered proposals must still be charged; treating those additions as free would fabricate savings. No new architecture or shortlist size is chosen here. The current IL64/RL8 experiment is unchanged; its first result should be interpreted as learning quality, not evidence that inference bypasses native planning work.
