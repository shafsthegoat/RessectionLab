# Independent generated-only review: proposed in-place InstanceNorm3d

**HOLD for model attachment or full128 retry.** This is a small CPU FP32 operator experiment, not a faithful replacement for the pinned native InstanceNorm3d. I did not load the checkpoint, run the network, or inspect patient data.

Candidate SHA-256 `89f32b947e9882784bc835e12002468c1616e43c134549cee703952c0af8d795`; generated test SHA-256 `e6e651d3ca600eab68cffa4b24cf5b50d04d1ab1407e7a800d004bb68aac6986`. I independently reran all five tiny tests in the pinned isolated Torch runtime; all five passed in 0.024 s. The native reference is `torch.nn.functional.instance_norm(input, None, None, weight, bias, True, 0.1, eps)`, which delegates to `torch.instance_norm` in the pinned installed `torch/nn/functional.py`. The candidate computes `torch.var_mean` over the complete D×H×W spatial map with `correction=0`, then applies separate in-place subtract, reciprocal-square-root scaling, affine multiply and add. This is the right *mathematical* full-map biased-statistics specification when input stats are used, and it avoids an explicitly slab-local normalization; it is not the same CPU floating-point reduction and rounding path as the native operation.

The three zero-centered random cases had maximum absolute difference between `4.77e-7` and `9.54e-7`, with no activation-sign disagreement. The low-variance constant-like case differed by `2.44e-5`. Crucially, the reproducible represented float32 tensor drawn near `1e6` with 0.1 scale had **maximum difference 1.7628903 and 43 activation-sign disagreements** versus native InstanceNorm. These are signs of intermediate activations, not decoded segmentation labels; no model/clinical effect was measured. This counterexample is far beyond the previously used `1e-3` logit-parity tolerance and rules out treating the current implementation as a numerically transparent replacement. Testing only centered Gaussian tensors would have hidden it.

The operator verifies inference mode, CPU float32 contiguous NCDHW shape, finite inputs/affine values and compatible channel lengths. It mutates the input tensor. A tensor can share storage with another live tensor while having `_base is None` (the generated detached-alias control shows this), so the operator's checks do not establish exclusive ownership. Before any network attachment, the exact Conv3d output's consumers, skip storage, hooks, and affine parameters would have to be proven disjoint. The candidate also makes full-size `isfinite` checks before and after normalization, so an actual peak-memory saving has not been measured and cannot be assumed from in-place arithmetic alone.

The smallest useful next investigation is an isolated, generated-only numerical study of the pinned native `torch.instance_norm` CPU behavior on a prospectively fixed grid of shapes, offsets, variances and affine parameters, including low-variance and threshold-adjacent cases. If no available native-compatible in-place path meets the fixed parity rule, discard this replacement and look for a different early-encoder memory reduction. Only after numerical fidelity is shown should a separate graph-ownership proof and matched guarded network test be considered. Do not tune an acceptance threshold after seeing a full-model output or present this prototype as a full128 remedy.
