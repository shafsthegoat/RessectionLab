# Generated 64³ lazy final-decoder concat comparison

Under the same pinned GlioMODA checkpoint, generated nonzero [1,2,64,64,64] input, CPU FP32 settings, tiled Conv3d adapter, and resource guards, both baseline and lazy-concat arms completed one instrumented forward. Saved logits are byte-identical to each other and to the earlier accepted tile1 reference; the predeclared 1e-3 logit tolerance and exact decoded-label rule both pass. Both finalizers were clean, host pressure remained normal, and the exact TractoInferno acquisition process remained within its allowance. This is numerical software evidence, not patient or clinical performance.

The baseline final decoder showed a 67,125,248-byte resident-memory rise from transpose output to stage input, matching the 67,108,864-byte full concat tensor. The lazy arm showed zero rise at that boundary. Sampled whole-process peaks were 757,415,936 and 749,420,544 bytes respectively: a 7,995,392-byte (~1.06%) reduction in these two instrumented runs. Forward times were 0.5374 and 0.5357 seconds; no robust speed advantage is established. Allocator reuse and other live tensors make the stage-local saved allocation a poor predictor of peak. The corresponding full128 concat is 536,870,912 bytes structurally, but full128 pressure and output feasibility remain unmeasured for this lazy arm.

This compact package binds exact contract, source, generated-input receipt, both supervision/result/log traces, comparison and independent audit. It excludes model weights, generated logits arrays, patient images, annotations and bulk output; the retained result files state each omitted logit SHA-256. The earlier v1/v2 monitor/startup negatives and full128 tile1 pressure negatives remain separate evidence.
