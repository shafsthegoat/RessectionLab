# Patient-size sparse mechanics: read-only feasibility audit

Scope: committed documentation, runtime/experiment receipts and official framework documentation only. I did not decode patient images, masks, surfaces or landmarks, run a mesher/solver, install software, or change tracked files. This is a proposal for a separate **non-patient** numerical benchmark, not an execution release or mechanical validation.

## What is observed, and what is only projected

- The RESECT Case4 v4 mesh is rejected: 19,070 nodes, 10,512 straight-reference tet10 elements; the unchanged bidirectional 2 mm surface gate fails at 3.869 mm source→mesh and 2.264 mm mesh→source *sampled* maximum (full-surface upper bounds 4.576/3.254 mm). Geometry generation took 17.632 s and sampled 591,118,336 B peak group RSS. No FEM solve was run. See `artifacts/mechanics/resect-case4-patient-mesh-boundary6-v4/RESULT.md` and independent review. Case4 V outcomes were previously exposed, and the estimated T1 envelope has known anatomical omissions. Neither anatomy nor clinical use is admitted.
- Its 57,210 unreduced displacement DOFs give the code's **conservative dense-profile Skyline projection**, `8*n*(n+1)/2 = 13,092,165,240 B` for one value array and `39,276,495,720 B` for three, before solver allocations. This is a storage warning, **not measured Case4 solver memory**. Actual Skyline profile, equation elimination, sparse fill, factor copies and nonlinear workspace are unknown. The host reports 17,179,869,184 B (16 GiB) physical memory; three projected full-profile arrays exceed it.
- A simple *pre-factorization* assembly bound for v4 illustrates why sparse storage is worth testing: each tet10 has 30 scalar displacement DOFs and at most `30*31/2=465` local symmetric scalar pairs. `10,512*465=4,888,080` pair contributions, so even storing every local pair once with 8-byte values and 4-byte row indices would be about **58,656,960 B**, plus column pointers. Duplicate global pairs reduce this count. A full unsymmetric 30×30 contribution bound would be **113,529,600 B** on the same 12-byte assumption. These are *not* measured or guaranteed FEBio CSC sizes: indices may differ, constraints can add fill, and sparse direct **factorization fill may dominate**. Do not use these assembly arithmetic bounds as a patient solve admission.
- The pinned FEBio 4.13 local build with a reviewed one-file repair to its Apple Accelerate CSC adapter passed eight actual tiny numerical controls, including a tet10 affine and multipoint-constraint check. All eight selected Accelerate; peak sampled group RSS was 45,416,448 B for the combined worker. That establishes basic software operation, not large-matrix stability. In the separate idealized HBE hex8 specimen work, a 28,233-node half model completed a single 639.057 s solve at 1,798,078,464 B sampled group RSS but failed its numerical accuracy screen; a 23,101-node full model earlier timed out at 420 s after logged step 36/60. Hex8, symmetry, boundary constraints and output differ from Case4 tet10, so these are **no extrapolated Case4 runtime or memory forecasts**. See `artifacts/mechanics-accelerate-controls-run-v1/RESULT.md`, `artifacts/mechanics/hbe-global-n32-execution-v1/RESULT.md`, and `artifacts/mechanics/hbe-resolution-experiment-result-v1/RESULT.md`.

The first technical question is **whether a non-patient tet10 finite-strain problem of approximately Case4 algebraic size can be solved accurately within a declared local budget**. It is not which framework yields the most realistic animation. Retain the geometric planner as the baseline.

## Smallest discriminating non-patient benchmark to freeze next

1. Reuse the pinned repaired FEBio runtime, its exact Accelerate solver profile, and the previously checked tet10 Ogden law/units. Use a Gmsh-generated 10 mm cube, straight-reference tet10, explicit `elastic-solid` domain and eight-point integration. Keep the constitutive parameters **numerical gauges**, not brain or patient estimates. Freeze a single source commit, mesh recipe and three spatial levels before execution. A structured six-tetra-per-cube design with `n=5,9,13` would nominally give `(2n+1)^3 = 1,331 / 6,859 / 19,683` tet10 nodes and `6n^3 = 750 / 4,374 / 13,182` elements if the generated incidence matches that design; verify actual Gmsh counts and quality rather than treating these numbers as observed. The finest level is slightly larger in nodes than rejected Case4 v4. A different Gmsh topology must be declared before running; no outcome-driven size selection.
2. Two load cases on each accepted level: (a) finite affine stretch/shear with prescribed external motion and free interior DOFs, checked against the analytic deformation/stress/reaction identity; (b) a simple fixed-bottom, displaced-top, traction-free-side case with a nonuniform field, so refinement and nonlinear solving are meaningful. Use **the same displacement, material, element, quadrature and solver tolerances** on every level. Repeat the finest nonuniform case with halved load step size for temporal sensitivity. This is at most seven native calls; stop immediately on the first numerical, time, memory or integrity failure. No patient data or measured specimen response is involved.
3. Proposed *predeclared* resource limits, consistent with existing local supervision: one numerical thread, 3 GiB sampled process-group RSS, 600 s per largest native call and 1,800 s aggregate, 512 MiB active output, one attempt per case, no retry, fallback, extra package or cap increase. These are suggested gates, **not demonstrated needs or an execution authorization**. Preserve partial logs and distinguish sampled RSS from an exact peak. Capture assembly/factorization timings and memory if FEBio exposes them, actual backend selection, equation count, matrix nonzeros and failure code; report unknown fields as unknown, not zero. Hash source, decks, runtime and outputs. A 16 GiB host makes the 3 GiB working budget relevant but does not guarantee isolation from concurrent workloads.
4. Numerical acceptance requires complete states, finite displacement/stress/reaction, positive sampled deformation Jacobians and reference Jacobians, prescribed-motion error, independent force/moment balance, actual residual norms below frozen solver criteria, and the affine analytic check. Compare nonuniform field displacements at fixed physical points **and integrated reactions** over all three meshes and the finest load-step repeat. Freeze an absolute numerical error allowance in metres/newtons before running; absent a justified allowance, report convergence trends rather than declaring pass. Report solver breakdown and matrix/factor growth; a successful process exit or fit to an assumed cube is insufficient.

**Decision boundary:** if the finest non-patient level completes within the frozen budget and numerical checks, it supports *solver feasibility for a similar-sized idealized mesh only*. It cannot admit the rejected Case4 geometry, identify patient material properties, validate displacement against observations, validate retraction/cutting forces, or feed RL rewards. If it fails, preserve the failure and diagnose memory, factorization, conditioning, element/formulation or tolerance separately before proposing a new version. Before any Case4 FEM, independently resolve the fixed source-envelope anatomy and 2 mm bidirectional surface failures, then prospectively bind a valid mesh, constraints, physical observations and a numerical convergence design. The current geometry and physical-fidelity gates remain closed.
