# Independent Gate A v2 pre-execution review

Decision: **GO for one prospective generated-only 32×64×64 CPU control under a naturally accepted, serialized quiet-host preflight.** A separate MPS call requires the CPU result and resource trace to pass and receive independent review. This does not authorize a 128³ model patch or patient inference. Gate A v1 remains the failed compressor-growth-guard experiment without reinterpretation.

No model call had occurred at review time.

The [Apple XNU pressure sysctl](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_memorystatus_notify.c) returns dispatch masks, whose [definitions](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/event_private.h) are 1 normal, 2 warning, 4 critical. The [XNU VM note](https://github.com/apple-oss-distributions/xnu/blob/main/doc/vm/memorystatus_notify.md) includes compressed anonymous pages in available memory. Compressor growth alone has no validated 256 MiB hazard threshold, so making it diagnostic-only in a separately versioned v2 is defensible. This cannot establish what the unsampled kernel pressure state was during v1. The cited source is current Apple XNU rather than an exact installed-kernel source tag.

The v2 CPU/MPS worker is unchanged from the vetted Gate A v1 worker: fixed generated FP32 input and pinned file hashes, four exact scoped NumPy safe globals with `torch.load(weights_only=True)`, strict nnU-Net architecture/alias checks, MPS CPU fallback disabled before import, MPS allocator fraction set before MPS tensors, synchronized MPS forward, and no patient arrays. CPU and MPS run as separate one-shot children; no output directory may already exist. A 3 GiB **sampled** child-group RSS limit, 120 s wall limit, 2 MiB log limit, and nonzero bounded MPS allocator remain. RSS and Metal allocator accounting are not summed.

The 30 s preflight requires sampled kernel mask 1, available indicator at least 45%, stable by at most five percentage points, nonincreasing swap-used reading, and no classified project compute overlap at any RSS. All host commands have a 0.1 s timeout and parsing fails closed. During a child the supervisor targets 0.15 s samples and rejects sample start gaps or sample duration over 0.2 s; it stops on mask 2/4/unknown, available indicator <30% or >20-point fall, swap-used growth >128 MiB, project compute overlap, RSS/time/log caps, or monitoring errors. It records compressor occupancy and rate without a compressor-only stop. Swapout/pageout counter increments or a post-run warning cause a HOLD rather than a success. Post-run sampling now applies the same pressure guard. These are prospective project thresholds, not Apple safety guarantees; brief changes between samples can be missed.

The process inventory uses macOS `ucomm` for executable class and command arguments only to identify project context; exact ancestor PIDs and the model child PGID are excluded. Nonancestor project Python/FEBio/pytest/node/shell work blocks, while curl transfers are allowed. No command arguments are stored in receipts. The writer's read-only launch fixture and this reviewer’s live parser snapshot confirmed the classifier and parser complete without a model child. The reviewer’s snapshot returned kernel mask 2 and 44% available at that moment, so launching then would correctly defer; wait for a naturally accepted preflight without loosening thresholds or interrupting downloads.

The comparator now requires `accepted_for_pair=true` in both supervision receipts, in addition to valid result/logit hashes. It retains the predeclared `rtol=atol=1e-3` continuous-logit check **and** exact final decoded-label equality. Near-zero FP32 logits may cause a strict label failure even if continuous outputs agree; per-region threshold margins and crossings are reported separately. A numerical Gate A pass would only establish CPU/MPS parity on generated input, not segmentation accuracy or clinical validity.
