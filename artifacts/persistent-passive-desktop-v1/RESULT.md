# Persistent paired-tool desktop workflow

The Electron app now executes the fixed generated paired passive protocol,
displays both complete tools through six discrete states, and restores a saved
selection only after the backend reconstructs and validates its replay. Source
images, support, target, physical frame and tool dimensions are bound before display.
The adapter is deliberately fixed to the reviewed v1 generated fixture. V2
registration-dependent movement remains a backend capability, not a UI claim.

Validation: 72 focused canonical Electron/renderer/workspace controls pass
(1.834 s). Four App save-switch controls pass again against the clean staged
version after integration isolation. TypeScript and Vite build pass from an
index-only copy that excludes unrelated interface work. The bundle-size warning
is retained. The original interface patch reapplies exactly; both other edited
interface files remain byte-identical. Canonical Electron tests reuse the same
existing generated JSON fixture instead of their staged path-specific fixture.

renderer admission requires exactly two tools/six states; the fixed TS adapter
