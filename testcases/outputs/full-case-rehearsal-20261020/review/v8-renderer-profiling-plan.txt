The receipt lists each input/output, exact byte bounds, selected tick count,
raw tick timestamps, and script URLs. A newly-created isolate starts at byte0.
Original logs are never overwritten. All non-tick code/library/source/move
records, even outside the tick window, stay byte-identical and ordered so code
addresses can be interpreted; only complete in-window tick records survive.

For EACH relevant filtered log separately (substitute its actual filename):
  "$REHEARSAL_NODE" --prof-process --nm=/usr/bin/false --call-graph-size=12 "$REHEARSAL_PROFILE/windows/ACTUAL-ISOLATE-v8-renderer.log.window.log" > "$REHEARSAL_PROFILE/ACTUAL-ISOLATE.profile.txt" 2> "$REHEARSAL_PROFILE/ACTUAL-ISOLATE.profile.stderr.txt"

--nm=/usr/bin/false deliberately omits expensive/unreliable native symbol
decoding from stripped Electron libraries; JavaScript/JIT names still come
from retained code events. Do not use --ignore-unknown: report unknown ticks.
Retain stderr and reject unsupported log grammar or pervasive unaccounted ticks.
Bundled Node v24.19.0 processes the tiny synthetic log as2ticks/0unaccounted;
this proves the workflow, not compatibility with every future Electron record.

Map each isolate by its script-source/code-creation URLs, not filename alone:
- incrementalSurface.worker-*.js => modeled surfaces (positions/index/normals).
- sourcePickingBvh.worker-*.js => picking BVH construction.
- index-*.js => main renderer/React/admission work.
- node:electron / main.cjs only => Electron main; not surface-worker evidence.
An isolate filename is not a native thread ID. Multiple URLs in an isolate and
new workers must be reported honestly. Do not merge isolated address spaces.

Source maps
The exact built assets include .js.map files. Bundled Node's --source-map
tick-processor option is BROKEN on the synthetic check (ReferenceError:d8 is
not defined); do not rely on it. Process logs normally, then map a generated
one-based LINE:COLUMN from a hot function against the corresponding saved map:
  "$REHEARSAL_NODE" "$REHEARSAL_ROOT/testcases/outputs/full-case-rehearsal-20261020/review/v8_map_location.mjs" "$REHEARSAL_PROFILE/maps/incrementalSurface.worker-ACTUALHASH.js.map" LINE COLUMN
The helper uses node:module SourceMap, no packages/browser/network. It returns
the original file/line/column and any mapped name. Pick the map whose exact
hashed bundle URL appears in the function name; source maps cannot recover a
missing code entry or distinguish two files using the wrong bundle map.
